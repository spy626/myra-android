## First integration slice (code written 2026-09-19)

- Reuses the existing `WorkspaceChatGateway`, shared writing/intent/context and OkHttp client. `WorkspaceGroqFree` is a bounded text-only endpoint with a pinned model ID, no web/code tools, no Gemini Voice API key, no extra memory/router/database and no changes to Safe Edit executor.
- `API & Cloud Settings` has an explicit **OFF-by-default** Free-tier + inference-ZDR switch. A saved key alone does not activate Groq. Short normal text chats choose Groq only after opt-in; if the latest prompt is above a conservative local length budget and an OpenRouter Free key exists, the pre-existing hard-$0 OpenRouter route is selected. No automatic cross-provider retry after a failed request.
- Groq receives bounded recent same-chat text and shared writing instructions; the existing saved-memory interceptor runs only for the OpenRouter endpoint. Groq never receives saved personal memory via that interceptor. Photos/files with Groq enabled are blocked before sending, not silently switched to another provider. Project source is not automatically included. Coding requests keep the original Safe Edit flow.
- Groq accepts a maximum 12000 characters of bounded input message text locally and reserves 2048 completion tokens (a local heuristic, not an exact token counter). It refuses over-budget input without slicing the latest prompt. Only completed, bounded replies are persisted. 429 remains a reported failure or bounded same-route retry; there is no paid fallback.
- Tests cover request endpoint/key isolation, retained complete prompt or explicit rejection, attachment rejection, unfinished reply rejection and provider body secrecy. The existing gateway regression test now accounts for both explicit Workspace provider enums. The exact-activity patch passed unit tests and APK compilation in its temporary CI verification job; final signed CI/release and real-device test are separate gates.

## Installation and data safety

Existing Workspace conversation files are stored in Android `noBackupFilesDir`, and keys use installation-bound encrypted preferences. Uninstall may permanently erase local chats, keys and settings; having the key in Notes does not back up the chat history. Prefer installing an APK update **over** the existing app when the package name and signing certificate match. If Android rejects an in-place update, stop and investigate signing or version-code mismatches before uninstalling; do not promise recovery without a verified export/backup mechanism. Prefer a trusted password manager over plain/cloud-synced Notes for any API key.
