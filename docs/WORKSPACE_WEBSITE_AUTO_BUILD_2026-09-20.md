# Workspace website build: one explicit request, three project files

Implemented on `agent/myra-phase-1` only. A direct user request such as “build a website” promotes the selected chat to a website project. The same Send action authorizes generation and saving of `index.html`, `style.css` and `script.js` under that project, without a per-file approval dialog. Plain chat and requests for a prompt do not authorize project writes.

The previous one-file `replace_exact_once` (120-character oldText, 250-character newText and 2,048 output tokens) is not the website-build path. Website generation uses one bounded, zero-price OpenRouter Free request for complete three-file JSON. The model cannot choose a paid route or arbitrary paths; a failed, incomplete, malformed or non-JSON response does not apply the proposed files. A first failed generation leaves an empty project rather than pretending that a starter page is the requested website. Service-side HTTP 521 and lack of a suitable free provider remain possible and are not presented as successful builds.

Existing project source is read only from the three project-local files and screened for possible secrets before sending. The app rechecks task identity and source freshness before writing. A durable three-file rollback record is persisted before any writes. Undo refuses to overwrite newer manual edits. A subsequent explicit coding request can automatically finish the prior rollback when all generated files are unchanged; the user does not need to press Keep each time. Other project files and AIRI memory are untouched. There remain bounded file/context sizes for safe and feasible free calls; this does not grant unlimited whole-repository or Android build execution.

After all three file writes are verified locally the saved-project Preview opens. “Saved” is not proof the visual website meets the goal, and there is no claim of physical Android acceptance without a phone test. Existing single-file Android Safe Edit and its explicit write guard remain unchanged.

Physical phone acceptance: create a new chat and ask LYRA to build a Minicoy landing page with a heading and a working button. Confirm all three real project files in Work → Project Files & Editor, Preview shows the requested page instead of “Hello, Workspace!”, and Undo restores the previous state. Then send a follow-up without a per-file permission request; confirm changes appear only in the selected project. Separately verify a normal “Hi” does not start a coding project, no unintended paid provider is selected, and that an invalid/free-route failure leaves existing sources intact.
