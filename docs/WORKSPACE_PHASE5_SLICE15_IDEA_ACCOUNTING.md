## Implementation and authority

- Only after an approved/resumed task, explicit eligible file selection, full-file and task sensitive-pattern screening, current full-file SHA, local 1,500-character prompt preview, entered **session-only** API key and a separate dialog showing exactly which source and task fields leave the device does LYRA send **one** HTTPS POST. No upload of a whole project, no tool calling, no shell, no search grounding, no retries or paid fallback. The request uses **only** `openrouter/free` and `provider: {"zdr":true,"data_collection":"deny"}`. The secret key stays in a request header (not URL, body, file, preferences or log) and is cleared from the UI on send/leave.
- Leaving the screen cancels the request and invalidates its response. Response bodies are bounded; errors are sanitized and never display provider error bodies that could echo source/keys. A provider reply is not an instruction or permission. It is rejected when incomplete, too long, malformed, outside the chosen file, blocked, stale, paused/revoked or inconsistent with the saved task/source fingerprint.
- A valid suggestion appears **as a preview only**. The existing exact-file write confirmation and single protected backup/Undo/Keep remain mandatory. User-mediated manual JSON and clipboard workflows from slices 12–14 are preserved. A successful local file SHA/write is not a build, browser test or verified product completion.
- The external provider processes submitted text; per-request privacy routing and regex secret checks cannot guarantee that all sensitive data is absent or that any external provider is risk-free. User should use only non-confidential test code and a free account with no billing. API credentials are not included in GitHub commits or tests.
