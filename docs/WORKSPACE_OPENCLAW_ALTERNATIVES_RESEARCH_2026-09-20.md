# OpenClaw alternatives — LYRA free-model and architecture research

Research date: 2026-09-20. User-supplied directory: [T31K/awesome-openclaw-alternatives](https://github.com/T31K/awesome-openclaw-alternatives/tree/7d5cf1601ee866083695398e201d805cb81bc321), reviewed at commit `7d5cf1601ee866083695398e201d805cb81bc321`. This is a curated **list of assistant runtimes**, **not** a free-model/API provider or a ready-made Android library. Its root currently contains only `README.md` and no repository-level license file. Do not copy its text or code into LYRA as if licensed. Several metrics and repository names are outdated; each linked upstream must be checked separately. No API endpoint was live-tested with the user's keys, no new provider was integrated, and no free-tier/cost guarantee was inferred from a GitHub README.

## Concrete LYRA adoption gate (ideas, not an implementation claim)

1. Keep **one** Kotlin Workspace provider route owner, one AIRI/Plast-Mem memory owner/Room truth, current task and source authorization, explicit cross-provider website-source consent, source SHA freshness and protected Undo/Keep. No new provider client or external installer just because an alternative agent advertises it.
2. Before any new route: audit exact provider+model+endpoint+account tier for recurring $0, no card/AutoPay/overage, privacy and provider retention; validate JSON schema/tool support, context, output, quotas and HTTP error shapes. Store only non-secret route capability/health metadata and honor cooldown headers; do not print raw keys. A definitive 400 may be a *permanent request-schema* rejection, not a rate-limit. Check local schema compatibility before retry; do not replay uncertain network timeouts or loop providers.
3. Verify one real Website task from approved complete brief to saved `index.html`, `style.css`, `script.js`, visual DOM/Preview checks and working button, while keeping unrelated files and Undo. Keep no-cost deterministic layout and file checks local; do not claim human-equivalent visual perception or actual phone-pass from emulator/CI alone.
4. Read upstream source, license and commit for the **individual** project before using any code. Do not run fork-linked installer scripts, scrape undocumented proxies or misuse consumer OAuth/subscription credentials. Only user-authorized, trusted local/LAN endpoints may receive source.

This accounting does **not** promise zero errors, new free models, a new APK, or compatibility with the user's current phone. The linked directory is a discovery source, not proof of provider availability or safety.
